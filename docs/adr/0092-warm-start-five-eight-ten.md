# ADR-0092：warm 启动门槛调整为 5 / 8 / 10 ms

状态：Accepted（需求调整，实际性能验收仍开放）；日期：2026-11-11；需求 PERF-03、QA-01、REL-04。

## 用户要求与决策

用户在讨论 warm 启动中位数后明确要求“5ms以下即可”，随后将原 p95≤5 ms、p99≤10 ms 明确为 8 ms、10 ms。当前 warm 门槛因此调整为 **p50≤5 ms、p95≤8 ms、p99≤10 ms**。本决定替代 ADR-0029 及后续文档中的原 2 / 5 / 10 ms 数值，不改写历史采样或历史失败。

`warm_start_ms` 仍从 launcher 接受已鉴权请求计至 VM 完成本次唯一绑定并确认可执行，包含持久准入、准备和审计；不改为队列弹出时间或完整 HTTP 响应时间。保持 Linux、OSv 的指定机真实 KVM、每条必要路线至少 1000 个成功正式样本、原始数据/候选/宿主/配置/工具摘要及尾延迟计算规则。

cold 的 400 / 600 / 1000 ms、snapshot 的 100 / 150 / 250 ms 及其启用条件不变。功能、一次性 VM、租户隔离、崩溃恢复、取消/配额、一般安全、宿主就绪与资源/长稳条件保持。仅有小批诊断数据或宿主未就绪的数据仍不能登记为正式通过。

## 实施与验证

先完成[自评审](../../PUBLIC-QUALIFICATION.md#private-evidence)，同步机器契约、门禁脚本、当前需求矩阵和 README。用定向检查验证 4.8 ms 可满足新的 warm 中位数，超出 5 / 8 / 10 的对应分位数仍拒绝；不足千次、缺失隔离用例或未就绪宿主继续拒绝，cold 门槛保持。

[ADR-0091](0091-single-durable-pristine-checkout.md) 的实际 ABBA 已完成，见[诊断结果](../../PUBLIC-QUALIFICATION.md#private-evidence)。测量起止、脚本字节和原始样本保持不变，按新门槛解读结果。门槛调整不使已有诊断数据自动变为正式发布证据，也不要求为了文档数值变更重复完整 KVM 功能回归。
