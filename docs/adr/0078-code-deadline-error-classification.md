# ADR-0078：代码执行观察期限与传输异常

状态：Accepted；日期：2026-11-06；关联 API-02、LIFE-01、QA-03，承接 ADR-0072。

rc72 实机代码测试在 `timeout=.3` 的执行观察边界收到被 urllib 包装的 URLError，SDK 以 TransportError 返回，未符合此场景的 TimeoutException 契约。此前代码、上下文、富结果与显式取消均通过；本次失败仍阻止候选验收。底层网络原因的文本已由传输层脱敏，不能仅凭该异常类型宣称服务崩溃。

决定：仅在 E2B 代码适配层捕获传输错误时，立即比较单调时钟与执行观察截止时间。截止已到则以 TimeoutException 返回，保留原错误作为 cause、已知 execution 句柄，并沿既有独立取消与终态确认流程清理。确认失败仍抛 CodeCleanupError，不能被超时分类覆盖。未到截止时间的短请求超时或其他传输失败保持原 TransportError；原生异步句柄的独立观察/不自动取消规则不变。Python 与 Node 使用相同规则。

实施前自评审：只包裹提交与日志查询RPC，不在外层统一捕获时改写，否则用户回调自己抛出的TransportError也会被误分类。不能把所有网络异常都当执行超时，也不能在等待清理之后才判断截止，避免把早于截止的真实网络失败误分类。保持已有TimeoutException、已知4xx拒绝、用户回调异常、AbortSignal、协议错误和清理错误的原有处理。分类不重试或重放提交，不以取消ACK证明终止。准备阶段的40秒等待与执行观察期限仍分别处理。

验证：先用受控时钟在实际SDK原生控制器上注入传输失败，覆盖已越截止与尚未截止两个分支，并验证一次提交、已知ID和取消确认。随后定向双SDK套件、类型声明；SDK字节变更进入新候选冻结CI及同包实机验证。Rust/guest镜像字节未变，依据 rc72 的摘要绑定复用68组guest验证，不因此重复Rust/QEMU整套回归。

2026-11-06 验收：见[rc74同包验证](../../PUBLIC-QUALIFICATION.md#private-evidence)。双架构实际guest70组、447输入完整CI、ARM离线包QEMU48组及指定服务器五夹具全部通过；本决定已实施。正式发布继续遵循功能、性能和一般安全基线条件，未据此关闭原完整目标。
