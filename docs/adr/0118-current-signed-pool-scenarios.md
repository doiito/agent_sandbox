# ADR-0118：当前候选的池空、真实签名到期与镜像代次激活验收

状态：Accepted（当前Linux三个专项均已独立核对通过，全部后端场景登记继续）；日期：2026-11-13；2026-11-14补验；需求 LIFE-04、SEC-03、QA-01、QA-02、PERF-03、OPS-01。

## 验收范围

rc88已完成[完整功能基线](../../PUBLIC-QUALIFICATION.md#private-evidence)，原18场景仍缺实际pool_exhaustion、artifact_expiry、template_rotation的当前候选证据；OSv原25项脚本还绑定旧诊断模板。保持原18定义和40项范围，本批补Linux三个缺口，OSv随后使用当前签名Python模板适配，不把unsupported输入拒绝登记为只读挂载证明。

只用原rc88签名包的程序/VMM/kernel/基础guest，私有验证目录和systemd units，共用原flock、mTLS、身份/cgroup及独立清理。自评审先于工具实现；脚本变化只跑定向守卫和本批真机，不重跑不变产品的完整CI/15套。未通过结果原样保存，新ID纠错，不重放业务。

## 四个独立夹具

池空分别建on_miss=reject/cold夹具：单个128MiB profile，min=max=2，refill burst=2、速率0.1/s；active/物理/身份上限均4，租户并发4。启动供给消耗初始burst，在下次token前领取并保持两个warm session，独立记录ready=booting=0、active=instances=2、仍有物理/身份及租户余量。第三请求必须命中同profile的empty路径：reject为429且没有执行/领取，cold为实际新VM执行并记录empty/cold。不能用租户quota或全局active满冒充池耗尽；若时序前置条件不成立，批次失败而非反复发请求。关闭原session并确认原VM回收。

到期夹具使用原测试公钥实际信任的Ed25519签名，短有效期元数据在本地交付前生成，私钥留项目内且不发往服务器。生产签名CLI的至少一小时限制保持；私有签名工具仅生成有界短窗测试数据，再由当前真实验证器核验。进程首次加载时签名仍有效，能力摘要须与该原始manifest一致。加载后真实墙钟到期，不改系统时钟、不替换已加载文件：idle退休、新租户准入拒绝、无新领取；到期前已准入任务按现有生命周期语义验证完成与回收。任务跨过到期边界的请求/结果/审计及原PID代次分别记录；全局/租户尚有余量，不能把quota拒绝算到期。

轮换夹具使用同基础guest离线派生A/B镜像，各含不同的只读`/etc/osv-pool-generation`内容；使用本地debugfs只写新复制的镜像，原资产不变。更新镜像SHA、大小、SBOM组件与签名，验证器及离线BOM schema检查通过。先从A原预热VM实际读A，再按当前支持的停止API/launcher、原子替换私有配置、重启流程激活B。原A活动/idle VM及PID代次必须全部退出，旧请求摘要拒绝、旧session不复活，B领取必须来自新ready实例并实际读B。该证明明确为重启激活，不宣称热切换或不断流。

## 资产、前置条件与失败

签名fixture资产放项目`build/validation`中；原64MiB镜像和kernel仅复制，不修改实际依赖，不将不同镜像的结果冒充原包无变化。验证前核对包90项载荷及1243项程序输入，派生差异完整记录；到期窗口在投递前冻结，服务加载时须仍有足够执行时间，窗口不足为夹具失败。私有准备器只增加推迟服务启动选项，使配置在首次加载前落定，保留原默认行为及全部宿主/namespace/身份检查。

每次只运行一个全局锁内业务任务，总超时1800秒、日志8MiB；HTTP超时覆盖有界的跨到期任务。只对本夹具unit操作，无全局控制器、swap、时间或安全策略变更。异常在finally停止服务，核对run/cgroup、进程引用和凭证；派生资产原件与唯一证据留项目内，服务器/安装重复副本在逐项SHA及无引用后清理。

本批不是性能采样，不登记全部后端case通过。warm仍5/9/13ms、四必要路线各1000正式样本；先补必需场景，源码稳定后集中性能验收，K8s继续暂缓。

实施前审查见[自评审](../../PUBLIC-QUALIFICATION.md#private-evidence)。

## r1前置条件失败与r2定向补验

r1的emptyreject/emptycold两个夹具已通过；轮换在A执行之后、尚无idle补齐时触发“无A idle VM”的前置条件失败，尚未执行激活B。任务保持失败，三夹具独立清理证明与原档保留。r2只补rotation/expiry，不重跑两个已通过场景；以有界观察等待A原活动owner仍在且至少一个idle ready，再执行同一停止/激活断言。新增守卫反例覆盖仅active、active+booting仍不满足、active+ready满足、owner丢失失败。真实guest/候选与A/B签名资产字节不变，短期manifest按新任务重新签发。

## r2到期夹具失败与r3单项补验

r2轮换已通过；到期夹具未进入跨期执行。原审计记录一次run.admitted随后unavailable拒绝，没有pool.claimed；当时签名仍有约425秒，夹具据此请求约445秒任务。当前Linux job准备协议明确上限300000ms（session的600000ms不适用于job），只提高验证配置上限不能改变协议。原终态仍失败，不登记到期通过。

r3只补expiry，复用原包和基础镜像，签发4分钟测试manifest，首次加载及请求前都核对真实剩余窗口。纯函数同时约束45至270秒剩余时间、跨期sleep与15秒结果余量、请求超时不超过配置及job协议300000ms，保持原配置的300000ms上限。窗口不足或过长在发请求前失败。线程若提前返回API错误，立即记录结构化状态/错误码，不再仅以“owner未出现”隐藏原因。finally在清理前保存原审计、报告及服务状态；不修改生产协议、候选源码、时钟或原r1/r2证据，不重跑已通过的轮换/池空或完整CI。

r3也保持失败：本地签名到期为12:11:22Z，原任务实际启动为12:19:44Z，已晚于签名窗口。已取回原终态及输入未变证明，最后日志显示尚未产生launcher锁时清理助手又要求该锁，完整归档及独立清理复查因SSH断开尚待取回。不能登记为运行中签名到期、不能声称清理已独立验收。下一次应将验签、交付和单次提交放在同一控制器调用中，消除分步调用间的墙钟空档，并处理服务从未启动的清理分支；先完成原r3取证，不盲目重发业务。

阶段核对见[当前签名池场景](../../PUBLIC-QUALIFICATION.md#private-evidence)，保留r1/r2父任务失败与各成功子场景的区别。

## r4控制器与清理修正

先导出原r3归档及独立清理结果，新的expiry任务才允许开始。r4使用单个`launch`控制器调用，依次进行只读前置检查、冻结和签名、交付、单次提交及原ID观察；签名后不再跨人工/工具调用边界等待。仍用4分钟测试签名及原45至270秒任务窗口，不延长产品job协议或放宽时效断言。

失败路径直接调用已合格的隔离cleanup，再从保留的audit目录复制证据，不依赖从未启动的launcher已创建锁文件。成功路径保留原stop_group的owner锁、进程/cgroup退出检查。新增定向检查重现“服务未启动且无锁文件”的失败清理，以及新ID/结果路径和单次launch调用顺序；不重跑不变产品CI或已通过业务。

2026-11-14补充：SSH控制连接也曾在分步调用间过期。私有运输包装器在本地静默读取已授权密码，经匿名管道交给sshpass；同一进程连续认证、原r3导出/清理复核及r4 launch。密码不进入argv、环境或文件，签名仍在全部批准及原取证完成之后才生成。任何步骤失败立即退出；观察失败只查原ID，不再次执行整条启动链。
