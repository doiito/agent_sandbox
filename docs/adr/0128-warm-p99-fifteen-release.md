# ADR-0128：采用15ms warm p99并优先发布

状态：Accepted；日期：2026-11-17；需求 PERF-03、QA-01、QA-05。

用户明确要求“性能目标修改为p99<=15ms，先发布”。warm门槛改为p50≤5ms、p95≤9ms、p99≤15ms；四必要路线、每路线至少1000样本、原18类池场景、普通安全和功能验收范围保持。cold门槛及ARM无网QEMU/ARM KVM豁免保持；K8s和过期域名证书验收仍暂缓。

不再推进尚未完成实际guest/API验收的ADR0127预封存实验。两个guest源文件已精确恢复rc92已验收实现，实验源码/程序/库/四镜像及资格证据留项目；不将其纳入此次发布，不采其计划的ABBA。原所有13ms门槛下的失败收据不改写；按新政策另立复核结果。

rc92的原始千次warm为3.131/6.012/14.245ms，满足新目标；OSv warm及两条cold也在范围内。正式发布仍须满足ADR0123的签名、当前来源和具体候选绑定，不能靠旧rc90证据、旧包补元数据、放宽候选身份来放行。已知rc92旧包缺现行构建身份，按当前工具生成新的完整候选，优先复用字节相同的功能基线，仅补实际变化涉及的安装/签名/来源与必要同包启动验收。不得重复采样凑绿。

正式包采用受控正式签名及干净的可审查发布源码快照，测试签名包仍受安装根限制。目标架构运行无需下载、容器或编译器；实际库和资产留项目。发布索引记录每架构包、安装器、公钥指纹、摘要、已接受验证及明确暂缓项。公开发布/安装仅在实际门禁通过后执行；本ADR不预先宣称已发布。

自评审：用户变更直接同步机器契约和边界反例，历史结果保持；产品恢复避免将未验收实验夹带发布。源码快照必须逐项对应当前源、排除私钥和验证凭据，保留完整来源；正式签名和包内所有文件继续由候选逐字比较约束。普通安全之外的增强项不新增为此次阻碍。
