# ADR-0117：补池进程提前退出的失败归类与退避

状态：Accepted（rc88完整功能及真实补池故障回归通过；新候选正式性能继续验收）；日期：2026-11-13；需求 LIFE-04、QA-01、PERF-03。

当前rc87四路线延迟达到5/9/13ms及cold阈值，但[池故障r2](../../PUBLIC-QUALIFICATION.md#private-evidence)未通过新增补池失败检查。原29项Linux池基础检查全通过，故障限制已恢复且独立清理完成。保留的实际审计显示补池反复created→boot_cancelled，没有refill_failed；不得把未触发预期内核事件或零失败计数记作通过。

源代码中fillOne把VM生命周期取消反向传播到补池context，同时用返回错误是否含context.Canceled来排除失败。当VM在准备就绪期间异常退出，probe因VM死亡返回取消，也可能被当成调度器主动取消，从而跳过失败计数和按profile退避。先用实际一次性helper子进程退出、原产品代码及独立审计反例复现；PID限制具体导致新VMM退出的路径和原r1的503仍分别保留，不仅凭此推定内核行为。

保持准备期间由probeGuest对VM死亡即时取消RPC；将“VM结束时回收600秒补池定时器”的反向回调延后到成功发布ready之后。失败路径在主动清理之前按补池context是否被显式取消、池是否已停止来判断取消归属，不能仅看probe错误。真正进程退出、探测失败及启动deadline计为补池失败并退避；调度回收、内存压力、模板失效或shutdown的主动取消不计失败。成功发布后VM结束仍释放补池context，不遗留定时器。

不更改请求重试、租户准备、所有权持久性、CPU预算、四槽默认或最新延迟阈值。先以私有Go overlay保存新增反例、在原代码上记录失败，再采用最小产品修复并运行定向测试和race回归。产品改动后原rc87完整CI、签名包与正式性能仍是原候选的证据，不能冒充新二进制验收；后续必须新候选冻结、编译/包验证、功能及必要性能回归。

执行前完成[自评审](../../PUBLIC-QUALIFICATION.md#private-evidence)。不重放原r1/r2故障任务，不抹去原失败，不把这项原池管理功能修正扩展成增强安全或K8s工作。

## 实施结果

[rc88功能基线](../../PUBLIC-QUALIFICATION.md#private-evidence)完成一次完整CI、双架构90/75载荷离线包、x64非root安装/API及ARM无网卡QEMU61组。指定机原15套/516+44项、原VM前台6200ms维护、额外Linux池29项及实际补池拒绝/退避/恢复均通过，六个新任务各执行一次并独立核对回收。

原r2补充读出26条匹配其新VM的内核拒绝记录；Linux6.1在fork所在叶级计数，父计数为0未否定实际拒绝。新故障任务按私有路径、boot、VM及时间匹配内核记录，观察失败计数0→1及394ms剩余退避，恢复后总失败计数2与两条refill_failed审计一致，池重新达到desired并执行warm任务。新工作点的正式启动千次、原18场景其余项和原40项未完成要求继续开放，不移用rc87延迟证据给新包。
