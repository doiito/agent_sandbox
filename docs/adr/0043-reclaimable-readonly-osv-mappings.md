# ADR-0043：只读文件映射的驻留诊断与安全回收

状态：Proposed；日期：2026-11-02；需求 OSV-02、SEC-03、PERF-01、QA-01/02/05。

## 原因

rc49 的签名无 ROFS 段缓存策略在 128MiB 通过完整 20 项 Python 功能，但 64MiB 科学任务仍失败。分配器用量约 85MiB，Python 小块 arena 为 27MiB；不能把二者的差全部归为可回收文件页。此前普通匿名小页原型对实际工作量没有降低占用，已经撤回，不能再次以合成结果代替真实任务。

无缓存 ROFS 的文件映射走逐页读入的私有 VMA；已有通用 pagecache 支持 owned/borrowed 页、COW 和映射 PTE 记录，但不能直接对所有 read_cache 项加简单 LRU。借用段、私有重定位页和可写页的所有权不同。

## 顺序与约束

1. 先使用现有 `/proc/self/maps`、mincore 与 sysinfo 测量各阶段 VMA 驻留，分开匿名、只读权限文件、可写权限文件、未由 VMA 覆盖的分配器内存。先在未触及的匿名区验证 mincore 不提交物理页，再触及一页并验证驻留改变。固定上游 x64 page fault 在普通 VMA fault 前处理 safe_load fixup，这为非侵入测量提供依据，仍须实机验证。
2. 驻留映射之和不是唯一物理页或 RSS 的严格证明，权限只读也不证明可丢弃：RELRO 页可能曾被重定位写过。诊断只给出上界和候选来源，不据此宣称 64MiB 已达标。
3. 仅在数据表明有足够空间时实现回收型只读映射。普通 read 不恢复永久段缓存，映射采用有明确所有权的页；COW 后的私有数据脱离可回收集合，借用页及非本策略文件系统不受影响。
4. 预算/压力淘汰必须先阻止新映射、清理所有 PTE，再完成跨 vCPU TLB 同步，最后归还页。不能套用仅用于当前 fault 的“单 PTE 不 flush”例外。映射释放、分割与页表寿命要与现有 MMU 锁序相容。
5. 不允许分配器在持有缓存锁时等待同一缓存的回收。明确元数据预留、预分配或 emergency allocation 约束，回收路径不做可能无限等待的分配/I/O；有界失败不能变为死锁或损坏数据。
6. 原型默认关闭，只有签名 kernel/模板策略可启用；CLI 不接受租户自定义 boot args。固定版本、完整负载、原 30 秒任务期限及 VM 每任务销毁约束不变，不能用更多 RAM 关闭 64MiB 原目标。

## 验证

实施前[自评审](../../PUBLIC-QUALIFICATION.md#private-evidence)。先诊断并保留结果，再确定实现；若有代码改动，覆盖文件内容/尾零、同文件多映射、COW、RELRO/可写数据不丢失、并发 fault/munmap、TLB 与内存压力，之后运行原完整科学矩阵。冻结候选后一次 CI 和受影响真实冷/warm/故障回归；仅诊断工具变化不重复 Linux rc46/QEMU 或原生 49 项。
