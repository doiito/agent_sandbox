# ADR-0007：离线自包含发布与安装

状态：Accepted；日期：2026-10-29；需求 REL-04、SEC-05、OPS-01。用户确认“离线零依赖”指目标机器离线安装和运行，不要求目标机器离线从源码编译。

## 决策与边界

发布为 Linux x86_64 与 aarch64 各自独立的版本化单包；包名和签名 manifest 均声明目标架构，安装时必须与宿主架构一致。两个架构的 Firecracker、jailer、guest kernel/rootfs 不可混用。包内放入静态链接的 API、launcher、安装/验证工具，匹配的 Firecracker/jailer、guest kernel/rootfs、`mkfs.ext4` 及其动态加载器/库闭包、systemd unit、无秘密的配置模板、签名 artifact manifest 和 SBOM。目标机器不运行包管理器，不下载容器镜像，不需要 Go/Rust/编译器，不访问外网。OSv 原生 agent 成熟后按同一包格式增加可选 guest profile；当前只有经独立生产门禁的 Linux 路径可激活。

“零依赖”不表示摆脱宿主 Linux：必须预先具备匹配架构的 Linux、KVM、cgroup v2、systemd、受支持的内核/文件系统及足够资源。安装器验证目标架构；激活前的 doctor 检查 KVM、cgroup 等宿主能力，不满足就拒绝生产激活。域名证书和租户密钥属于部署秘密，不进入通用发布包；离线安装可以完成，但只有配置了有效 mTLS/策略、通过 doctor 和发布门禁后才启动服务。当前 `nas.deployment.example` 证书过期，因此域名 TLS 验收保留待办。

## 完整性与部署

构建侧按固定清单收集文件，拒绝符号链接、设备、未知文件和秘密路径；文件摘要/大小/权限写入规范化 release manifest，再由离线 Ed25519 私钥签名。目标侧必须从独立可信渠道取得 release 公钥及验证工具摘要；内嵌在包中的公钥不能自证可信。验证先于解包安装，拒绝路径穿越、重复路径、超限大小、非预期类型、过期/错误签名及摘要不匹配。发布包以固定顺序、归零 uid/gid、固定 mtime 生成，给定相同输入、构建时间戳和签名密钥应得到同一字节序列。

正式打包必须来自干净的 Git 工作树，release manifest 的 `commit` 才能作为源码修订声明。带未提交更改时默认拒绝打包；仅验证候选可显式设置 `RELEASE_ALLOW_DIRTY_TEST=1`，在 manifest 的 `commit` 中标注 `-dirty-test`，并使用测试签名密钥与 `.test-signed.tar` 命名。签名仍证明包内字节完整性，但这种候选不能凭 HEAD 提交号声称源码可复现或正式发布。

安装使用同文件系统临时目录，全部文件校验、写入和 fsync 完成后，以版本目录原子 rename 提交；不覆盖运行中的版本。systemd 配置使用明确版本路径，升级前检查新版本、停旧实例并完成审计/任务收尾；切换失败可回到旧版本。安装程序不自动启动未知证书/密钥的生产服务。发布验证、安装、回滚和断网启动均需真机证据。

## 验收

1. 编译/链接检查：所有随包宿主程序及其库闭包在目标 OS 基线上无需额外安装包；`mkfs.ext4` 通过包内 loader/库调用。
2. 签名与归档负向用例：篡改、缺失、重复、路径穿越、错误密钥、过期、特殊文件、超大条目一律拒绝且无安装副作用。
3. x86_64 在阻断外网的真机上安装并运行 API→launcher→VM→guest；核对 cgroup/UID/审计/清理。aarch64 按用户本轮确认，验收交叉编译、包安装及 QEMU 内功能，不以 ARM64 KVM 真机作为本轮门禁；QEMU 不证明 Firecracker/KVM 在 ARM64 宿主上的行为。升级/回滚不混用旧新制品。
4. 发布身份：记录源提交、工具链/构建器、所有文件摘要、SBOM、版本和候选测试结果；未执行的门禁不宣称通过。
