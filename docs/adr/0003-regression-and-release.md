# ADR-0003：分层回归与候选制品证据

状态：Accepted；日期：2026-10-29。对应原方案 §6.6/R10，需求 QA-01～QA-05、OPS-01。

## 决策

执行顺序为设计 → 有记录的自评审 → 实现 → 定向测试 → 合并 CI → 批量真机与发布验证。自评审是作者检查，不冒称独立第三方评审。

每次编辑只跑受影响检查；PR 做 Go test/vet/race 和两个 Rust crate 的协议测试/静态构建。文档变更只做结构/跟踪矩阵验证。合并候选或手工触发才做一次真机完整 E2E；guest/driver/kernel/VMM/安全边界变更强制做真机。周回归合并全部累计变更并串行使用指定机器；长稳/大样本性能/全兼容矩阵只在 release 或对应变更触发，开发循环不高频运行。

对同一候选和同一测试配置，已通过的昂贵任务不重复跑；复用键包含源码内容、构建工具链、制品摘要、测试用例版本、宿主基线/配置。任一变化或上次失败/证据缺失则失效。测试不能只按 Git HEAD 缓存（有工作区修改）；不能复用不同硬件的性能结果。PR 可以取消过时 CI；正在运行的真机/故障演练不得自动中断或并发重启。

网络或观察超时先检查原 process/session/systemd 状态，确认终止才重跑。不把 timeout/skip/mock 记为通过。失败重试最多一次且必须标记首个失败和原因；逻辑错误不靠重复运行变绿。

CI 保存命令、退出码、候选源码摘要、工具链、用例计数、JUnit/JSON 和摘要清单；含环境信息的原始证据放受控目录/流水线 artifact，不提交私钥或 token。mock、进程集成、真 KVM、生产验收分别命名。发布要求所有必须项有当前通过证据、可回滚制品和未完成项归零；配置了 workflow 不能声称云端 CI 已运行。

## 后果

开发反馈保持短而确定，完整回归集中批处理；需要专用有标签的受控 KVM runner，不能让 fork PR 获得服务器凭据或 root 执行权。未配置 runner 时真机 gate 为待完成，而不是跳过即通过。
