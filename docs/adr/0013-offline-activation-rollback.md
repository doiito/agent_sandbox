# ADR-0013：离线版本切换与回滚门禁

状态：Accepted；日期：2026-10-29；需求 REL-04、OPS-01、SEC-05。继承 [ADR-0007](0007-offline-self-contained-release.md)。

## 背景

安装器已在目标机离线验签并原子提交版本目录，但 `current` 的手工修改没有机器可执行的停机、残留和已安装字节校验。安装后文件可能被误改；只检查旧 tar 签名不足以证明将要运行的目录仍与签名包一致。

## 决策

在静态 `osv-offline-release` 增加 `switch`。操作员提供原始签名 tar、带外 release 公钥与部署根目录；该命令只变更部署根目录内的 `current` 相对符号链接，不启动或停止服务。先完整验证 tar 的签名、有效期、宿主架构和全部 payload，再逐文件核对已安装的 `releases/<version>-linux-<arch>`：必须只有清单中的普通文件，大小、权限和 SHA-256 全部相同，不接受 symlink、额外文件或可被非所有者修改的目录。没有 tar 或公钥时拒绝切换；回滚对旧版本运行同一命令、同一校验。

切换前在 `run_root/.launcher.lock` 上取得非阻塞独占锁，以证明没有持锁的 launcher；检查生产 API/launcher 两个 systemd unit 均为 inactive，`run_root` 与指定 cgroup 根目录没有 `job-*` 残留。任何状态不可读取或有残留均拒绝。持锁期间重检已安装版本和当前链接，使用同目录临时相对链接 + 原子 rename 切换，再 `fsync` 部署根目录。当前链接若是目录或指向版本目录之外，拒绝覆盖。部署根、版本根和运行根必须已存在且由当前管理员拥有，不能是 symlink 或对组/其他用户可写。

含 `-dirty-test` 修订标识的候选默认拒绝切换；隔离目录演练须使用名为 `osv-offline-validation-*` 的部署根并显式传 `-allow-test-candidate`。本命令不自动批准生产启动：证书、租户策略、宿主 doctor、正式签名和运维审计仍按发布门禁检查。测试签名的隔离演练不能当作正式激活证据。

## 自评审

| 风险 | 处理 |
|---|---|
| 已安装字节在安装后改变。 | 切换前把每个安装文件与新验签 tar 的清单重新核对，并拒绝额外文件及链接。 |
| launcher 重启与切换并发。 | 持有和 manager 相同的 `.launcher.lock`；锁冲突时立即失败。 |
| systemd 停机后仍有旧任务资源。 | 检查运行目录与 cgroup 的 `job-*`，有残留拒绝；人工继续审计独立于此门禁。 |
| 切换中断留下半个链接。 | 临时链接与 `current` 位于同一目录，原子 rename 后 fsync；旧版本目录不删除，可用同命令重新验签回滚。 |
