# ADR-0102：在 VM 就绪前完成一次性控制连接握手

状态：Accepted（已实现并通过同包功能验收；真实 API 收益与正式性能门禁开放）；日期：2026-11-12；需求 LIFE-04、PERF-03、QA-03。

## 依据与决策

[补池并发对照](../../PUBLIC-QUALIFICATION.md#private-evidence)未使尾延迟达标，降低并发还使 paced 供给下降 16.8%，因此保留原并发/配额/最低水位，不增加固定等待。下一步将与租户无关的 UDS/vsock CONNECT 握手移至 VM 成为 ready 之前；绑定、输入准备、持久归属提交、审计和 guest ACK 仍在领取计时内。不能据此承诺尾延迟收益，必须用同负载真实 API 对照确认。

Linux fc-agent/v3 当前每个连接只处理一个请求，pristine ping 不占租户请求预算，accept 后的收发超时为 5 秒。因此无需修改 guest 协议或复用已执行连接：启动 ping 验证后建立一个空白控制连接；下一次健康 ping 或 prepare 独占消费它，随后按原路径关闭。健康 ping 成功后重新建立空白连接，供下一操作使用。一次 prepare 后永不重新预连接或把 VM 放回 pristine 队列。

连接作为 `vmInstance` 的临时资源拥有，不放入跨 VM 全局连接池，也不写入 lease/snapshot。就绪前的独占构建阶段或 `controlMu` 串行区负责取走/替换连接；VM 生命周期取消必须直接关闭对应连接，取消回调只操作捕获的连接实例，避免触碰后续连接。实例 ID、原 PID/start ticks、签名规格与原 lease/cgroup 校验保持。

## 边界与失败语义

- 首版仅在已实际验证 pristine revision 2 的 Linux 池、健康间隔不超过 1 秒时启用；OSv、直接驱动及更长健康间隔保持原路径。健康与 prepare 共用原序列化/编解码/帧和身份校验。
- 建立连接的操作在原检查截止时间内且最多 1 秒；缓存空闲上限为 2 秒，留在 guest 5 秒读超时以内。取用时重新绑定本操作的取消/截止时间，不能继承建立连接的短期取消导致立刻关闭。
- 前台任务可能暂缓普通健康检查。已持有空闲连接的 VM 到期前必须允许有界维护，和原健康检查共用最多 4 个工作槽；不能在长前台任务期间一直跳过，等 guest 读超时后才发现整池失效。销毁同步取走并关闭 idle 资源，取消回调只关闭其原连接。
- 超时、连接缺失、VM 取消、身份不符或预连接失败均不得宣告 ready。未发送 prepare 时可按原规则先销毁 VM 再重新选择；一旦尝试发送准备帧，任何不确定结果继续销毁，不能重试绑定。
- 关闭一个尚未发送请求的连接可能使 guest 进入拒绝状态；因此过期/损坏连接所属 VM 必须退出池，不能悄悄换一个连接后继续把同 VM 当 pristine 使用。
- 首次 verified readiness 的 cold_boot 记录位置保留；额外连接准备计入完整 cold admission 和后台 ready 供给。warm_start 原七阶段及全部持久/准备边界不变，不将绑定工作移到计时外。
- 不放宽 CPU、内存、并发、FD/任务上限、TTL、审计、一次领取或租户隔离。额外 idle FD 随 ready VM 数量有界，必须纳入泄漏与供给观察。

## 顺序与验证

先完成[自评审](../../PUBLIC-QUALIFICATION.md#private-evidence)，再实现 VM 所有权资源及共享 transport 注入点，避免复制一套 prepare 解析逻辑。定向测试覆盖真实 CONNECT 在 ready 阶段完成、健康消费并补接、prepare 只发送一次、取消/过期/损坏/丢 ACK、回调与消费竞态、不同 VM 不混用及停机 FD 清理。

新宿主代码稳定后集中冻结一次候选，运行受影响 Go/race/vet 与原生命周期/取消/租户/恢复集，再完成同包 CI、x64 KVM 和 ARM 编译/QEMU。guest、mimalloc 构建资产及协议保持原字节。真实 API 对照需同时报告 warm/HTTP/池等待/供给/内存与失败，最后才考虑正式千次门禁；不因实现看似合理就宣称性能通过，也不重放旧失败任务。
