# ADR-0110：以不变平均CPU预算验证rc87的周期等待

状态：Accepted（受控实验，尚未改变产品或证明收益）；日期：2026-11-13；需求 PERF-03、QA-01、REL-02。

## 依据与决策

[当前rc87定向证据](../../PUBLIC-QUALIFICATION.md#private-evidence)将两个准备长尾关联到同VM cgroup、成功throttle返回和vCPU可运行等待，重叠6.810/6.850ms；另有后台审计fsync等待，分开保留。旧rc38的10ms周期实验未改善当时readiness长尾，慢窗口也未观察到节流增量；原负向结果保持。当前证据覆盖不同候选、准备路径及实际节流区间，支持针对该条件进行一次新因果对照。

以已完整功能验收的同一rc87签名包执行A1/B1/B2/A2，A的quota/period为100000/100000µs，B为5000/5000µs。两者每vCPU平均预算均为1核；5000位于当前配置允许的1000–1000000µs周期范围，使用既有配置和jailer传参。未采用此设置为发行默认值。

## 不变量与顺序

先完成[自评审](../../PUBLIC-QUALIFICATION.md#private-evidence)。四组各128正式+5预热，复用原未跟踪benchmark及qualified准备器，正常生产doctor、CPU2–5/NUMA0、128MiB/1vCPU、无swap、max_booting=2/health=1000ms和全部七阶段保持。不增加固定等待、CFS跟踪或诊断绕过。

变因仅为quota和period的成对变化。规范化只允许已核验的夹具路径/临时监听端口以及这两个确切字段；检查单独改变period而使平均CPU预算变大的反例。逐条核对实际cpu.max为所属组预期值，原签名包/90项载荷、唯一VM/PID代次、持久归属、审计、租户/取消/TTL和资源上限保持。

保留全部请求、失败、超时、拒绝和冷回落；原不可变任务提交一次，连接观察失败只查原ID，不因慢样本重复直到变绿。候选程序未变，复用已通过完整CI/E2E；只验证新配置准备/规范化/预算反例和实际API组，完成后独立核对原数据及清理。

## 解释与采用

分别报告每组和每种策略合并的warm/七阶段、HTTP、就绪等待、paced供给、观测RSS/CPU窗口及失败。已有CFS精确证据作为机制依据；本批宽CPU窗口不能单独解释具体准备阻塞。

准备阶段和完整warm需有重复方向的收益，功能/失败不退化；HTTP、供给或内存的明显回退必须解释，不能仅以局部延迟采用。若对照不支持，保留现行100ms并继续处理已证等待。通过短窗也只支持候选选择，同配置千次、四路线、资源/长稳及原40项要求仍须满足；后台审计持久性不因周期实验而改变。

## 2026-11-13执行结果

[原任务ABBA](../../PUBLIC-QUALIFICATION.md#private-evidence)532次全部成功。A/B合并warm为3.416/9.817/14.292和3.255/8.109/16.725ms，准备阶段p99为7.484/7.955ms；B的paced供给下降约2.45%，池等待p95/p99上升。没有证明预定的重复方向完整warm/准备收益，**不采用5ms周期，保留100ms默认值**。原始证据全部保留，当前正式p99及四路线门禁继续开放。
