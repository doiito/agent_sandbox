# ADR-0103：用原签名候选做预连接真实 API 对照

状态：Accepted（对照已完成；有实测收益，正式千次门禁开放）；日期：2026-11-12；需求 LIFE-04、PERF-03、QA-03、REL-04。

## 决策

[rc86](../../PUBLIC-QUALIFICATION.md#private-evidence) 已完成预连接功能、完整 CI、双架构离线包、ARM QEMU 和同包指定机回归。下一步仅运行真实 API 对照，不再次执行完整功能回归或重建候选。A 使用原 rc85 签名包，B 使用原 rc86 签名包；顺序为 A1/B1/B2/A2，每组 128 个正式请求和 5 个预热请求，共 512+20 次。原包、签名、载荷摘要、源码差异和 guest 一致性必须绑定，不能把重编译的旧程序冒充原基线。

四个独立安装目录依次启动、测量和清理，任意时刻只有本组服务/VM 运行，共用指定机验证锁。每组运行后验证原 PID/代次、服务 InvocationID、原始请求与 VM 唯一性、持久审计、全部载荷和清理。失败停止后续组，原失败/日志保留；观察超时只恢复同一任务的观察，不能重跑已有组。

两候选使用相同 kernel、镜像、VMM/jailer、128MiB/1vCPU shell 任务、CPU 2–5/NUMA0 实际放置、100% 单核配额、无 swap、最低水位和 max_booting=2。使用已冻结的原准备器、startup_benchmark 与放置校验，不改动 warm_start 七阶段、完整 HTTP、ready_wait 或原始分位数计算。路径、目录名及候选版本通过精确替换归一化后配置必须相等；原配置与摘要同时保存，其他差异不得静默忽略。

执行首轮 `rc86-control-abba-r1` 时，A1 的 128+5 次成功；B1 在采样前被配置一致性检查拒绝。原准备器为各独立网络命名空间随机分配本地 API 端口（A1=34463、B1=55459），该变化原先未纳入归一化范围。原失败、A1 原始数据与两个目录的清理保留。修正仅用于新的 r2 任务/目录：先保存原配置、摘要和归一化配置，再做比较；显式验证顶层 `listen` 为 `127.0.0.1:1024..65535` 后，仅把此临时 API 路由端口规范化。每个实际值仍保存，不改变准备器、协议、认证、资源、工作负载或计时。若尚有其他差异，检查继续拒绝，不扩展通配忽略规则。任务体中的签名 manifest 绑定按各原包精确核对，任务参数其余字段保持一致。

签名包除两个主进程外，还存在其他宿主二进制构建标识和签名/SBOM/许可证归档字节差异；完整差异清单必须报告。该实验衡量两个已验收候选的整体差异，不据此单独证明一次 CONNECT 的因果成本。

## 观察与判读

报告每组及每候选合并的 warm/HTTP/ready_wait p50/p95/p99/max、七阶段、失败/超时/冷回落、paced 完整批次速率、初始最低水位等待和 20ms 采样的 VMM RSS。批次前后额外记录 API/launcher 的实际 PID 代次、FD 数和 RSS，以及已归属 VM 的 FD/RSS；不在计时请求中增加追踪或改变原采样器，不将这些边界观察称作 FD/RSS 峰值或长期无泄漏证明。

复查独立宿主状态、正常生产 doctor、实际 CPU/内存放置及无残留。每候选仅 256 个正式样本，不能登记为正式千次门禁或缩小原分母。若收益不稳定或供给/资源退化，保留结果并继续定位；不得通过减少补池、放宽限额、增加固定等待或排除坏样本使门槛变绿。正式 warm 目标保持 p50≤5、p95≤8、p99≤10ms。

先完成[测量自评审](../../PUBLIC-QUALIFICATION.md#private-evidence)，再冻结验证工具和计划。产品源码、guest、构建资产和正式门禁证据本批不修改；整体目标仍按原 40 项矩阵跟踪。

## 实际结果

[r2 对照](../../PUBLIC-QUALIFICATION.md#private-evidence)完成 512+20 次，四组全成功且独立核对。256/候选合并 warm 从 3.727/9.384/17.675ms 降到 3.308/7.554/9.700ms，paced 速率下降 0.34%，ready_wait 中位数增加 4.20%；各组、阶段、资源边界及全部原始数据均保留。B1 单组 p99=11.458ms，短样本不代表正式达标。保留预连接实现并先进入 Linux warm 千次测量；原 r1 失败不改记成功，四必要路线和其余发布条件保持。
