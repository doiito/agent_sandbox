# ADR-0108：对完整功能通过的 rc87 执行正式启动采样

状态：Accepted（执行顺序与证据要求，性能尚未通过）；日期：2026-11-12；需求 PERF-03、QA-01、REL-04。

## 依据与决策

[rc87 同包功能验收](../../PUBLIC-QUALIFICATION.md#private-evidence)已通过一次完整 CI、双架构离线包、ARM 60 组、指定机原 15 套/560 项及 6200ms 同 VM 维护。此前精确监听的引用对照证明空闲 CPU 收益，但每函数仅 256 个正式请求，不能证明当前签名包的千次启动门禁。

按 ADR-0104 的顺序，先对同一 rc87 x64 签名包测 Linux warm **1000 正式+5 预热**。测量器与 qualified 准备器保持原字节，使用正常生产 doctor、原七阶段起止、CPU2–5/NUMA0、128MiB/1vCPU、100000/100000 quota/period、max_booting=2、health=1000ms。使用冻结候选绑定文件获取实际摘要，不继承 rc86 摘要常量；新工具/目录/任务 ID 与原证据分开。

测量链已由原正式千次、同源 API 对照及新整包功能验证，不新增短 pilot，不重跑未改程序的完整 CI/E2E。完整保留失败、超时、拒绝、冷回落与慢样本，不重复直到变绿。若该必要路线不达 **p50≤5/p95≤8/p99≤10ms**，先处理其明确差距，再执行其余三条必要路线；若达到，继续同包 Linux cold、OSv warm/cold 各至少千次。四路线与原 18 项隔离/恢复用例、资源/长稳和 40 项需求范围保持。

## 执行与复核

先完成[自评审](../../PUBLIC-QUALIFICATION.md#private-evidence)。提交前核对当前程序与功能基线、实际包/载荷/公钥、原测量器和准备器，指定机五个原功能任务已终态且未重放、锁可用、新任务/目录不存在、KVM/CPU/NUMA/无 swap 条件。保留程序、源码、设计、工具、计划、候选、配置与宿主摘要。

一次不可变 worker 执行业务，连接或观察中断仅查询原 ID/InvocationID；不得因观察超时重放。终态后独立核对原始分位数、七阶段总和、1005 个唯一任务/VM、实际载荷与放置、配额/正常 doctor 和清理。paced 包含等待/校验/落盘，不称饱和吞吐；阶段归属不等于阻塞根因。

新样本只属于 rc87；旧候选、直接调用或短窗不能替代。单路线达到延迟阈值也不等于完整性能或正式发布通过，测试签名、原未完成要求及用户暂缓范围继续明确标记。

## 执行结果

[同包 Linux warm 千次](../../PUBLIC-QUALIFICATION.md#private-evidence)已完成，1000+5 次全部成功、1005 台唯一 VM；独立原始数据、七阶段、载荷/放置/配额、输入与清理核对通过。warm 为 **3.299/7.894/13.639ms**，p50/p95 达标，p99 仍超出 10ms，因此不登记性能通过。25 个 >10ms 中，最大阶段为 preparation 17、admission 4、ownership 3、audit 1；先细分这些等待，其余三必要路线暂缓但仍需验收。连接恢复只导出原终态任务，原失败保留，未重放业务或重复完整功能 CI/E2E。
