# ADR-0049：功能交付优先与基本安全基线

状态：Accepted；日期：2026-11-03；来源：用户明确要求“优先功能性开发和验证，安全性做到一般安全性就可以”。

2026-11-06 用户再次明确发布条件：“功能，性能验证合格后，确保一般安全性就可以发布”。因此功能与既定性能门禁均通过、基本安全基线合格后即可进入发布；增强安全审计不增加发布前置条件。[K8s 实现暂缓](0076-defer-kubernetes.md)，其余仍在范围内的功能和性能要求继续验收。

## 范围调整

功能推进顺序为：执行/会话、文件完整流程、双 SDK 与 E2B 兼容、流式和后台命令、运行时模板、MCP/网络/观测及离线安装。继续按设计、自评审、定向测试、冻结候选 CI、实际 E2E 推进。双架构离线运行、warm pool 生命周期与性能目标保留；未达目标继续如实报告。

基本安全保留：KVM/每任务或租户会话边界、pristine 池用后销毁、认证与租户权限、路径限制、签名/摘要/TLS、资源配额、超时/取消与回收、默认无网络和敏感数据不入日志。功能扩展沿用这些已有机制，做必要回归。

全面 CVE/逐库版本审计、强制完整扫描覆盖、长期 fuzz、独立安全认证与深入攻击面研究转为增强项，不作为基本功能交付的前置条件。既有发现和证据保留为后续事项，不改写成已解决。ADR-0048 的深入组件影响工作 Deferred；本轮停止继续下载、复现或改库。

## 实现约定

发布构建的安全配置默认为 `baseline`，增强扫描通过 `RELEASE_SECURITY_PROFILE=extended` 显式启用；未知值拒绝。只有 extended 要求固定摘要的完整扫描快照；baseline 保留全部既有隔离、权限、签名、有效期与回收要求，包内说明实际配置。测试签名/安装限制继续生效。证书续期按用户先前要求延后，不把过期证书改成可接受。

本调整不自动证明完整功能、性能或生产流量切换已验收，也不授权改动共享宿主全局设置。需求矩阵保留原始行，增强项显式标记当前范围，不再以这些项目阻塞功能开发。
