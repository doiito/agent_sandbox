# ADR-0084：可断线续查的单次验收任务

状态：接受；工具专项已验证，指定机批次待验收。日期：2026-11-09。关联：QA-01、QA-03、OPS-01；延续ADR-0003，不改变发布门禁。

## 问题

真实KVM批次耗时超过一次SSH观察。SSH断开不证明远端任务停止；旧的前台调用方式容易失去可查询句柄，重启整批又会重复创建夹具或污染回归证据。现有夹具还有自己的validation flock，父调度直接占用同一把锁会与子脚本冲突。rc78本地包已验收，指定机重新认证仍失败，先补齐恢复连接后的可靠执行入口。

## 决策

新增仅用于验收运维的Python标准库工具，提供submit/status。管理员指定不可复用的任务ID、argv、工作目录、有界期限/日志上限和输入摘要清单。命令不经过shell，不传入SSH密码或应用凭据；既有验收程序继续自己读取私有配置。输入清单必须绑定执行程序；工具另绑定自身和Python解释器。命令环境固定为基础PATH、locale和禁止pycache，不继承调用者的密钥/代理环境。

submit/status管理入口要求root；worker只操作调用者自己所有、0700且无符号链接的任务目录，不授予额外权限，因此相同worker可在普通CI用户下做真实进程验证。运行实际KVM时仍由root的systemd单元调用，不能把普通用户worker测试当作真实管理器验收。

submit先在私有任务根下原子占用ID，复制worker和规范化计划，再通过独立systemd transient service启动。启动请求失败或SSH丢失不能释放ID、删除记录或重放。相同ID和相同计划只查询；不同计划拒绝。worker另用O_EXCL领取一次执行权，即使unit被外部重复启动也不重复执行命令。

worker对全部输入执行前后核对摘要，保留退出码、持续时间、主机boot ID、进程start ticks、解释器和worker摘要。独立的宿主批次flock跨任务串行，不占子夹具已有的validation锁；忙时任务明确失败、不排队、不重试。CI与手工批量都应走同一入口；旧脚本自身的互斥约束继续保留。

实际测试命令在独立进程组中运行。标准输出和错误合并流式写入有上限的私有日志；超时、日志超限或worker收到终止信号时，停止该进程组并等待退出，失败收据不变成通过。脚本自身仍负责现有独立systemd夹具/VMM的finally清理，调度器不能凭命令退出代替零残留断言。systemd禁止Restart，设置KillMode和有余量的RuntimeMaxSec。

status同时观察持久收据与指定unit。systemctl超时/DBus错误返回观察失败，不能当作任务结束；可见running句柄继续查原ID。unit已失败或缺失但无成功收据时返回失败/中断，不会猜测通过。只有命令退出0、输入未改、日志/期限合格的完整收据才能证明该任务命令成功；业务KVM、功能、性能与清理结果还必须由原夹具报告逐项证明。

## 验证与边界

先做输入拒绝、同ID竞争/不重放、管理器观察失败、worker崩溃的定向测试，并使用真实子进程验证失去启动观察者后仍能完成、失败退出、超时、日志上限、进程组回收、输入篡改和批次锁。管理器调用边界可用固定响应验证，但没有真实systemd执行就不能声称真实unit验收通过。指定机恢复后先以同一工具提交rc78的原推理/回归及导入模板矩阵。

本工具不进入应用离线运行包，不改产品代码、签名包或既有性能要求。只触发工具定向CI和文档审计，不重跑未变应用的Go/Rust/ARM/KVM完整矩阵。原始失败、任务收据和必要worker保留；结束的验证副本按已有清理规则回收。
