# ADR-0123：正式发布绑定当前候选的实际载荷

状态：Accepted（实现、真实打包定向验证及完整 CI 通过；新完整候选发布验收仍待完成）；日期：2026-11-16；需求 PERF-03、REL-04、QA-01、BUILD-01。

## 问题

rc92 已完成四路线正式千次，Linux warm p99=14.245ms，超过用户规定的 13ms。当前启动契约仍保留 rc90 历史证据；原检查器只核对证据指向的归档，正式 builder 未将其与本次生成的载荷绑定。因此历史通过不能证明新代码、SDK、镜像或配置可以发布。

## 决定

正式构建显式提供 `RELEASE_STARTUP_CANDIDATE`（已验收的 x64 归档）、`RELEASE_VALIDATED_CANDIDATE`（当前目标架构归档）和 `RELEASE_CANDIDATE_PUBLIC_KEY`（外部提供的候选验签公钥）。启动检查器增加候选选择；四条必要路线必须指向同一指定 x64 SHA256。保留旧契约与证据，默认审计仍能审计历史，但正式发布不能使用未指定候选的历史结论。

使用既有 Go 离线 verifier 验证两个参考归档的签名、架构、期限及全部载荷。在构建前核对目标候选与 x64 候选的源码身份、Go 版本和版本/提交身份；amd64 必须是同一个归档。ARM KVM 继续按用户决定豁免，ARM 独立编译/QEMU 功能回执仍由原验收流程提供，本门禁不把 x64 性能宣称为 ARM 性能。

在现有 `docs/security-profile.json` 中增加版本化构建身份：项目运行时代码/协议、SDK、vendor、OSv/Linux guest 源、部署与打包脚本的确定性源码摘要、输入数量、Go 版本和构建 epoch。使用明确源目录，排除生成缓存和 build/target/results/dist；大型实际镜像、库与工具由归档的全载荷摘要和既有来源校验覆盖。该摘要不是替代完整 CI 冻结清单的声明。两架构的公共源码身份必须一致。

SBOM 和签名 artifact manifest 尊重非负整数 `SOURCE_DATE_EPOCH`。builder 未指定时为本次测试候选固定一个当前秒；正式构建从已验签目标候选读取原 epoch，并拒绝不同的显式 epoch。固定 epoch 时 SBOM 使用内容派生的 UUIDv5，包含最终组件集合；未指定 epoch 的独立 CLI 保留当前时间和随机标识行为。签名期限及最短时长校验保持，正式包期限仍不得超过 artifact 期限；固定时间不延长已过期候选。

正式构建最后逐项比较新 stage 与目标参考归档清单：文件集合、规范化安装权限、字节数和 SHA256 必须完全相同；拒绝链接、特殊文件、额外/缺少文件以及任何改动。**不忽略时间戳、签名、SBOM、文档、SDK或配置文件**，不做元数据内容替换。固定时间与相同 artifact 签名密钥使这些载荷可以重建一致。新版本号、clean Git 提交和外层发布签名可以变化，但实际发出的载荷必须是已验收的原字节。

在最终打包前重新检查源码身份与参考归档摘要，阻止构建期间的替换。未通过不得留下正式归档；打包器把实际计算的载荷清单与参考清单比较，并保留写出时第二次哈希校验，发生并发改变时删除部分输出。脏工作树测试候选模式保留，仍只能生成 `.test-signed.tar`；构建参考候选不会自动授予正式发布资格。

## 验证顺序与边界

先做[自评审](../../PUBLIC-QUALIFICATION.md#private-evidence)，再实现、定向反例及现有 release/security/startup 回归。重点证明旧 rc90 不能为 rc92 放行，缺少源码身份、跨架构来源不一致、时间/签名/SDK/配置/镜像变化、路径/权限/文件集合变化及构建中替换均被拒绝；真实 CLI 固定 epoch 的 SBOM/清单/签名重复生成必须逐字节相同。

这批只修发布工具，不改变 warm 计时、阈值、资源预算或已安装控制面运行行为。当前 rc92 的正式失败保持。待尾延迟有受控优化依据并且工具稳定后，再集中构建新候选、执行完整 CI/双架构离线/ARM QEMU/指定机受影响回归及必要正式验收。门禁修复本身不作为重采千次直到变绿的依据，也不关闭原 40 项其余要求。

实施结果见[当前候选门禁验证](../../PUBLIC-QUALIFICATION.md#private-evidence)：真实 rc92 签名和全部载荷通过核对，rc90 启动证据明确不能为其放行；真实基础载荷的 x64 重建逐项相同、SDK 篡改被拒绝、ARM64 交叉构建及公共源码绑定通过。隔离测试的模拟 SLO 只检验门禁流程。1924 项冻结输入的完整 CI 通过，八个双架构控制面程序与已验收 rc92 原字节一致；没有构建或发布新的完整功能候选。
