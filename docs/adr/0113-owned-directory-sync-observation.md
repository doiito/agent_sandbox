# ADR-0113：先绑定VM工作目录再解释持久化等待

状态：Accepted（观察器资格及一次实际API观察已通过；稀有慢例仍开放）；日期：2026-11-13；需求 PERF-03、QA-01、OBS-01、SEC-03、REL-02。

## 依据与问题

[3/4槽对照](../../PUBLIC-QUALIFICATION.md#private-evidence)显示4槽的p95和paced供给改善，但合并p99仍11.108ms，不能采用。B1有12.282ms准入、12.194ms归属；B2有7.607ms归属。分段计时不能说明其中多少是I/O、审计锁等待或调度。

当前源码的 `persistProcessLease` 依次写临时文件、Sync、rename、工作目录Sync；归属阶段随后还有独立的持久claimed审计。已有观察器可关联audit FD/字节偏移和syscall fsync，却不能把短生命周期lease临时文件FD或目录Sync可靠绑定到某VM。不能只按同TID/时间邻近猜测归属，也不能据此删除任何持久边界。

## 先做观察器资格

从指定机实际BTF推导file/inode/dentry父目录、mode及设备字段的偏移和类型；不跨内核照抄偏移。保存来源、布局与本地验证。设备身份以已校验的major/minor和inode比较，不能默认内核设备编码数值等于用户空间stat编码。

私有probe记录vfs同步的entry/return及设备、inode、父目录inode、类型和TID等元数据，不读取用户缓冲区、命令参数或文件内容。核对真实返回类型和失败返回语义。同步可以睡眠或跨CPU，配对以线程代次/调用栈为准，不能错误沿用CFS探针的CPU/TID键。前缀、后缀、丢失和未匹配区间显式未知，不填零。

先以两个独立私有目录的普通文件/目录Sync和失败对照在指定机资格验证：将实际fstat设备/inode与原始probe比对，包含非目标目录、FD复用、失败返回、跨CPU配对及缺失边界反例。完整返回/元数据匹配、零丢失/overrun/miss才允许后续API使用；失败控制原任务和证据保留，修正用新ID，不能重放业务。

## 再关联实际请求

在现有已核验lease/PID代次上固定工作目录FD，保留到批次结束，避免删除后inode复用。字段须经过原benchmark真实序列化路径保留，不能重复过去顶层inode字段被白名单丢弃的问题。限定FD/内存数量、时间和导出大小，异常时关闭所有FD并回收私有实例/probe。

新目录身份用于区分该VM临时lease文件Sync、该VM目录Sync和共享audit Sync。结合原UDS/ACK时间线和调度窗口，Go请求可能跨宿主线程，不能只用上一个syscall的TID推断下一阶段。只对身份和完整时间边界足够的样本报告关联；VFS与syscall嵌套窗口须去重。如需要CFS关联，只使用已资格验证的cgroup inode与成功返回守卫，不将旧entry指针当成功节流。

通过[自评审](../../PUBLIC-QUALIFICATION.md#private-evidence)、本地反例和真机控制后，再固定一次同4槽配置的未跟踪/跟踪观察，各128正式+5预热，正常doctor、原rc87、原每VM预算及七阶段保持；4槽仍是诊断工作点，不是已采用配置。所有成功、慢例、失败及观察开销保留。该批不登记正式性能证据，不以观察到的较快一组替换原负向对照。

本ADR不减少fsync、不引入异步审计或改变归属协议；若证据支持新的持久化设计，须另行设计、自评审与行为/崩溃验收。产品未变时复用原完整CI/E2E，仅对新增观察器定向验证。原5/8/10ms、四路线千次、18场景和原40项范围保持。

2026-11-13：[资格验证](../../PUBLIC-QUALIFICATION.md#private-evidence)完成21项本地反例及指定机15次Sync控制，设备/inode/父目录/返回全部匹配，零丢失/overrun/miss，独立回收通过。真机自然跨CPU返回数为0，迁移配对仅由本地反例证明；API多线程代次和VM目录固定仍待下一阶段验证。执行时设计/评审原文已另存冻结，未用此后状态说明改写原任务输入。

实际API观察的执行前补充：两个批次使用相同的目录FD固定包装器，最多固定256个VM目录，所有FD在benchmark退出的finally中关闭，发生身份/代次变化、符号链接或容量超限即失败，不关闭后继续收集。设备/inode、VM ID及PID/start ticks放入原cpu_snapshot，测试真实validate_job与JSON回读。既有CPU/cgroup包装器保留并叠加，核心benchmark原字节不变。

同步实例另外记录全在线CPU的task_newtask和sched_process_exit元数据，观察上限180秒；实际调用前后采集launcher各线程的TGID、start ticks及读区间。已有线程从其完成采样后才有保守确定边界；新线程代次以无丢失的出生事件标识并按CLONE_THREAD和已核验创建者代次继承TGID，不能把推算tick冒充实际/proc tick。线程退出或下一出生必须截断上一代，同TID再次出现不得跨代配对。采样与生命周期矛盾则失败；前缀/后缀和无法建立创建者的代次保留未知。只将完整、同VM目录身份的调用用于归属阶段关联，不因观察覆盖不足重跑业务。私有观察器按设置相反顺序结束，避免其他探针摘要误报或漏清理。

2026-11-13：[一次固定实际API观察](../../PUBLIC-QUALIFICATION.md#private-evidence)完成，两组各128+5、266次全部成功；133个跟踪请求的目录/文件同步身份与七阶段顺序完整，75次跨CPU返回正确配对，所有私有资源回收。A仍有10.018ms准入及11.712ms归属，B未复现，不能借B的小批分位数结案或登记千次通过。后续稀有事件观察须另行说明样本量及开销，不能重跑本任务直到变绿。
