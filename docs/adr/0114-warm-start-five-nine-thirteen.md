# ADR-0114：warm 发布门槛调整为 5 / 9 / 13 ms

状态：Accepted（用户明确调整规格，实际性能验收仍开放）；日期：2026-11-13；需求 PERF-03、QA-01、REL-04。

## 用户要求与决策

用户先明确“p99 放宽规格 修改为p99<=13 就可以发布”，随后明确“p95修改为 9ms”。当前warm启动阈值因此为 **p50≤5ms、p95≤9ms、p99≤13ms**，替代[ADR-0092](0092-warm-start-five-eight-ten.md)及当前机器契约中的5/8/10ms数值。执行前完成[自评审](../../PUBLIC-QUALIFICATION.md#private-evidence)，再修改契约、检查器、测试及当前说明。

warm_start_ms计时起止仍包含持久准入、客体准备和审计，分位数仍用最近秩法。Linux/OSv x64的warm/cold四条必要路径、各路径至少1000个成功正式样本、真实KVM、正常production doctor、候选/宿主/配置/脚本及原始数据摘要、原18个隔离/故障用例保持。cold仍400/600/1000ms，snapshot仍100/150/250ms及原可选条件。功能、一般安全及发布要求按用户此前要求保持，K8s继续暂缓。

不改写历史原始样本、原执行门槛或原任务终态。可用新规格重新计算现有合格数据的数值判断，但诊断、跟踪、小样本、未就绪宿主不能因此登记为正式证据。当前rc87正式千次warm为3.299/7.894/13.639ms，p50/p95在新限内，p99仍超13ms达0.639ms；4槽未跟踪128样本p99为13.885ms，跟踪128样本9.234ms不替代正式门禁。

## 实施与回归范围

同步warm-start-gates.json与检查器中的三项warm阈值。验证5/9/13边界包含等号、5.001/9.001/13.001对应分位数拒绝、不足千次/未就绪/缺失隔离仍拒绝、cold保持，正式数据evidence不因本次变更填入任何记录。

只更改政策检查和文档，不改宿主/guest产品实现、发布包、原benchmark或其计时。定向执行政策测试和文档/机器契约检查，复用原rc87完整功能CI/E2E；对冻结程序清单中唯一的政策脚本差异单独记录旧/新摘要，其他1241项和单独QEMU runner必须保持，不能泛化忽略scripts变化。

实施核验：[政策同步记录](../../PUBLIC-QUALIFICATION.md#private-evidence)的11项定向测试通过，现行门禁与原样本重算一致。发布强制检查仍返回未完成，未登记任何新性能证据。只有政策脚本一项冻结程序摘要变化，编译产品和离线包保持。
