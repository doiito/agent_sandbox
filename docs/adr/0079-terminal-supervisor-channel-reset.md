# ADR-0079：监督完成后的控制连接关闭竞态

状态：Accepted；日期：2026-11-06；关联 EXEC-01/02、LIFE-01/02、QA-03，承接 ADR-0065、0077。

rc72 原默认 shell 的真实 KVM SDK 回归在 cwd 权限拒绝时收到503。独立 QEMU 中直接监督器连续100次拒绝/复用通过，但同一生产命令处理逻辑在第二次拒绝后稳定报告 ConnectionReset，继而清理超期、使 guest 失效。前者不能替代完整处理链的验证，原始正反例均保留。

原因：上层已观察到 SpawnFailed 而 Complete 尚未到达时，会调用 stop。监督器已发送终态后关闭 Unix 控制连接，未读的取消字节可能使接收端在终态帧之后收到 ECONNRESET。现有处理把它当未确认监督故障，即使终态帧已经验证也立即使 guest 失效。

决定：已确认 no_start 的进程不再追加多余 stop。读取控制连接时，仅在已解析有效 Complete 终态的情况下，把 ConnectionReset 当作对端关闭；仍须监督 helper 正常退出、接收缓冲无残留、任务 cgroup 为空并完成清理，才确认任务结束。终态前 reset、截断帧、无ACK、helper非零退出及清理失败保持原失败/VM回收行为。

实施前自评审：不能忽略所有 reset，也不能以 SpawnFailed 单独证明清理成功；退出状态和 cgroup 证明不可省略。不能仅增加清理等待时间掩盖竞态。stop 幂等与已发送取消的处理保持；该改动同时适用普通命令和解释器私有控制，不修改任何用户命令、cwd或权限。

验证：先在正式 agent pipeline PID1 测试中增加重复拒绝 cwd、结构化失败返回及成功复用，记录原代码失败，再实施修复。双架构普通监督/实际命令/代码服务检查覆盖终态、早死、取消和解释器通道；重新构建 musl/mimalloc guest及其镜像，冻结新候选CI、双架构包、ARM QEMU、x64同包cold/warm/显式模板及旧SDK回归。rc73代码专项通过不能覆盖此故障；原性能和发布门禁保持。

2026-11-06 验收：见[rc74同包验证](../../PUBLIC-QUALIFICATION.md#private-evidence)。双架构实际guest70组、447输入完整CI、ARM离线包QEMU48组及指定服务器五夹具全部通过；本决定已实施。正式发布继续遵循功能、性能和一般安全基线条件，未据此关闭原完整目标。
