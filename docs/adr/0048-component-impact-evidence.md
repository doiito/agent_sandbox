# ADR-0048：组件级漏洞影响与可重放实证

状态：Deferred；日期：2026-11-03；需求 SEC-05、QA-04/05、OSV-02。用户后续明确功能优先、一般安全即可，按 [ADR-0049](0049-functional-delivery-and-baseline-security.md)转为增强项；当前资料保留，停止本轮深入分析。

## 问题

ADR-0047 的源码包查询覆盖了匹配，但不证明该源码包的每个二进制都包含漏洞。rc51 只有 libuuid，却匹配到 mount/nsenter；GCC 匹配包含编译器工具、模板头文件和真正运行库。另一方面，发行版仍在评估的旧 zlib 不能只因版本较低或某函数名缺失而豁免。

## 决策

1. 为每条匹配及每个发货组件单独建立影响档案，绑定原 advisory JSON 摘要、原始扫描快照、实际 SBOM 摘要、组件引用/版本及所有该组件文件摘要。原始扫描结果不改写，未知覆盖不因影响分析消失。
2. 源码取自该 Ubuntu 源版本的官方归档，校验 `.dsc` 的 SHA256 条目并保存原归档、打包补丁和来源。明确 TLS/摘要校验与已认证 APT/GPG 链的区别，不伪称已完成未执行的签名验证。上游补丁和声明另存准确修订/摘要；评论和 PoC 只作为需验证输入。
3. 组件/代码缺失须核对最终镜像、确切归属、编译单元/打包规则和库字节；动态符号缺失或单次 PoC 不复现均不足以证明漏洞不存在。静态复制、隐藏符号或上游/发行版判断不一致时保留 pending。
4. 有界本地探针对真实固定库执行，记录加载库路径/摘要、输入、退出与原始输出；不得改宿主全局配置。内存/时间有上限，不对外连接、不写越界数据，保留失败。需要复现的测试先建立阳性对照，再比较修复版本或源码控制流，不能把测试没触发当成修复证明。
5. 档案区分 pending、affected、fixed_pending_acceptance、not_affected_evidence_ready。末者是有证据可供评审的结论，仍不是自动忽略项；正式处置需受信审核/补丁准入，变更源码包、组件字节或 advisory 修订即失效。不以“都在 guest”或“通常不调用”替代证据。
6. 先分析和复现，再将真实需要的库修复合并为一个新运行时候选，一次完整 CI 与受影响 E2E；纯分析工具、文件/符号检查和来源采集只做定向 CI/断网流程验收，不重复原 KVM/QEMU 全矩阵。真实源文件与库均保留项目内，已无用的解包/编译缓存按清单退役。

实施前[自评审](../../PUBLIC-QUALIFICATION.md#private-evidence)。覆盖跨组件/版本/advisory、源/二进制摘要篡改、无正对照、不可复现与评审状态的负向测试。任何未证明事项继续阻止相应正式准入；完整 QA-04/生产验收仍按原需求矩阵推进。
