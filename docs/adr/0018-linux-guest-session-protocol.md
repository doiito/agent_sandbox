# ADR-0018：Linux guest 多命令 session 协议

状态：Accepted；日期：2026-10-30；关联 ADR-0017、API-02。

## 背景

`fc-agent/v1` 在一个 vsock 连接上执行一次命令，然后 PID 1 重启 guest。持久 Sandbox 需要在同一 VM 的工作区中执行多条命令，但不能悄悄改变 `/v2/jobs` 的一次性清理语义。

## 决策

保留 `fc-agent/v1` 的单命令与自动关机路径。新增 `fc-agent/v2` 的 `ping`、`run`、`shutdown` 操作，每次操作使用一条来自 host CID 2 的 vsock 连接，并返回带同一 `job_id` 的结果。`run` 沿用 v1 的命令校验、UID 降权、输出与超时边界；命令结束后杀死该次命令留下的 guest 子进程，保留 `/workspace`。guest 从启动起只在前 10 分钟接收新请求，并把已接收命令的执行超时裁到剩余租期；结束清理最多再用 250 毫秒。最多处理 100 次 v2 请求；host 后续还须实施更短或相同的租期与资源配额。读取请求和输出时使用有界长度与 I/O 超时。

本 ADR 只定义 guest 协议能力。host session API、租户绑定、持有 VM、审计、取消与配额未完成之前，不在对外 API 宣称 session 或 E2B 兼容，不改变兼容矩阵得分。rootfs 改动按 L1、L2 与离线双架构发布规则验收。

## 风险与验证

如果 v2 请求允许 guest 内普通进程连接控制端口，工作负载可能冒充 host 运行其他命令；因此接收时检查 vsock 对端 CID 2。每次 `run` 必须清理派生进程，否则后续命令会继承上一次进程状态。原 v1 的启动、执行、超时和自动关机需要回归；v2 的多次命令、状态保留、拒绝非法操作、TTL 和请求上限需要独立测试。
