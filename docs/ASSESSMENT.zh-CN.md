# 原方案评估与优化基线

日期：2026-10-29。输入：[原始方案](../PUBLIC-QUALIFICATION.md#private-evidence)；代码基线 `ce9a428`。原始方案保留为输入，不用后续实现倒改原文。本文件的判断与目标均不等于验收完成。

## 评估结论

方案的“一任务一 VM、默认无 NIC、不可变根盘、宿主强制限额”方向合理。OSv 值得作为单进程预构建工具的优化路线继续验证，但现有材料不足以证明它已具有 10–30 倍密度优势、亚百毫秒 API 延迟或通用 Agent 兼容性。建议有条件推进，用工作负载实测决定 OSv 投资，而不是先投入完整驱动和平台再验证关键假设。

竞争力应定位为：可私有部署、清晰隔离和可审计交付；OSv 的延迟/密度优势是待验证的增益。通用 shell/构建任务继续使用已有最小 Linux 后端；不能将该后端的验收替代 OSv 改造的验收。SDK/MCP、模板、文件和流式执行仍需交付，已有的固定 Rust 工具协议不能算通用 Agent 产品完成。

## 必须纠正的推导

| 原方案判断 | 评估与优化 |
|---|---|
| ~5 ms / 11 MB 可推导 API ready <100 ms | 上游只宣称某配置的启动/内存下限；签名验证、staging、jailer、guest ready、运行时初始化、网络 RTT 都未计入。分别测 kernel、guest-ready、host-run 和 HTTP；报告 cache 条件、样本数、p50/p95/p99、失败率。 |
| Python + 科学栈可在 64 MB 运行 | 没有包版本/真实工作集证据；先锁 Python、numpy/pandas 版本、输入集和 import/计算样例，测峰值 RSS/脏页/并发，失败则调容量，不篡改工作负载。 |
| 10–30 倍密度、TCB 小即更安全 | Guest 代码行数不含 host/KVM/VMM/控制面；VMM RSS、page cache、scratch、CPU/IO/超额预订决定容量。使用相同硬件、相同任务和安全设置对比成本/成功任务，不能用内存配置值除以 host RAM。 |
| OSv 内 syscall 策略、隐藏符号提供防护 | 同地址空间内的恶意代码可绕过 guest 钩子；只能作诊断和减面，强制安全策略必须在 host。Guest 自报审计不具有抵抗 guest 失陷的完整性。 |
| virtio 前端是 Guest→Host 主要风险面 | Guest 前端通常消费 host 数据；宿主攻击面重点是 VMM 的设备后端、KVM 和控制面解析 guest 数据。两端都要 fuzz，分别声明被保护的边界。 |
| 复用 httpserver 就不必设计协议 | TCP REST 路由不能解决 vsock framing、背压、取消、版本、结果真实性和上限；现有串口协议只作 OSv 诊断基线。新增 OSv vsock 驱动必须有独立接口设计及故障测试。 |
| virtio-fs / hotplug 作为通用文件路径 | 必须先核实固定 VMM 版本支持面；默认用独立只读输入盘，不向恶意 guest 共享宿主目录。输出通过有界协议并做路径/大小校验。 |
| snapshot / warm pool 默认安全可复用 | 不能跨任务复用已执行用户代码的 VM；只允许未来评审通过的 pristine 快照，并重建熵/标识/连接。当前默认冷启动。 |
| “E2B 风格”即 ≥80% 兼容 | 必须指定 SDK 版本、方法清单、语义和分母，用契约测试逐项计数；未支持方法返回明确错误，禁止静默换成不同语义。 |
| 9 个月即可 GA | 原文同时称 6–9 月、gantt 约 6 月，且未计算驱动维护/兼容修复/审计资源；改为有证据的出口门槛，日期为估计，不能用时间代替通过。 |

## 同口径竞争分析

| 路线 | 已有的一方资料支持 | 本项目需证明的差异 |
|---|---|---|
| OSv | 上游面向单 Linux 应用，列出多种 runtime，宣称可达 ~5 ms / 11 MB | 锁提交后的目标工具/语言依赖兼容、端到端延迟、成本及维护能力；不能宣称完整 Linux ABI。 |
| E2B | 官方提供 Linux VM、SDK、模板、暂停/恢复及持久化 | 私有部署的运维成本与有意义任务的成本；不直接比较官网启动数字和本地 kernel 数字。 |
| Daytona | 官方描述多租户 API、runner、snapshot、volume、调度与状态对账 | 单节点简化部署与生命周期可靠性；不能仅凭“容器派”标签推断其具体隔离配置。 |
| Modal | 官方提供执行命令、流式输出、文件/网络/快照接口 | 受控内网离线部署、同等功能和资源条件的成本；不以不明条件的“秒级”数字贬低竞品。 |
| WASM | 作为受限语言工作负载的候选路线 | 可选后续对照实验；本轮无 WASM 工作负载证据，不作数字比较。 |

以上是能力比较而非第三方性能复测。官方资料于 2026-10-29 核查：[OSv README](https://github.com/cloudius-systems/osv/blob/master/README.md)、[E2B](https://docs.e2b.dev/)、[Daytona architecture](https://www.daytona.io/docs/en/architecture/)、[Modal sandbox](https://modal.com/docs/guide/sandboxes)。架构推论由本文负责，不归为官方结论。来源可能更新；发布时须锁来源快照/上游 commit。

## 优化后的推进顺序

1. 设计：建立 ADR、原需求到验收的跟踪矩阵、威胁模型、分层回归策略；先明确功能缺口和证据口径。
2. 自评审：对取消/超时、结果来源、资源回收、权限、供应链、故障和证据完整性做代码审查，记录发现和修复标准。
3. 实现与定向测试：优先修复客户端取消、vsock 挂起和未配置 token；增加真实进程链路 E2E；CI 对快检/合并验证/真机验证分层。
4. 真机：在用户指定机器的独立目录验证现有 OSv 与 Linux 路径；核查 KVM、cgroup、jailer、身份、取消和零残留。宿主不满足生产条件时报告失败，不能改成绿色。
5. 继续功能：OSv vsock、运行时模板、流式执行/文件取回、SDK/MCP、观测、长稳与故障演练。各项完成前保持矩阵未验收，Linux 通路不是替代交付。

## 宿主和发布约束

本轮已核实指定机器通过 operator + sudo 可用，KVM/cgroup v2/Firecracker 已存在。root 直接密码认证被拒绝不影响 sudo 路径。宿主启用 swap，尚不满足项目生产 doctor；不擅自停用共享宿主的全局服务或 swap。原域名证书于 2026-10-12 过期，用户已明确先做其他工作；域名生产 TLS 验收保留待办，可用独立短期测试 CA 做 mTLS 协议测试，二者分别记录。

现有 `VALIDATION` / `METRICS` 的 2026-08 记录是历史参考；没有对应原始证据的结论不能作为本轮通过证据。生产发布需要当前候选源码摘要、制品摘要、测试环境、命令/退出码、用例结果和清理证据组成闭环。不得把证书/密码/token/私钥写入测试报告或仓库。

## 2026-10-31 性能证据补充

[rc37 两后端各千次 warm 诊断](../PUBLIC-QUALIFICATION.md#private-evidence)确认预启动领取已实际工作，但尚不能声称具备 1–2 ms 生产启动能力：Linux warm p50/p95/p99 为 4.939/23.762/41.929 ms，OSv 为 3.717/4.609/5.203 ms，完整 HTTP p50 分别约 178.761/109.027 ms。它们是不同最小原生任务，宿主 swap 开启且未固定 CPU/NUMA，既不能替代相同 Python/JS 工作负载，也不能直接得出产品密度或竞品优势。下一步按阶段定位长尾，再优化关键路径和进行固定基线的正式批次；目标保持不变，门禁继续未通过。
